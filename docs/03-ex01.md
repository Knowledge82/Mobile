# Модуль 03, ex01: Background

> Второе упражнение: приложение получает **фон-картинку**, общую для всех вкладок. Картинка должна быть уместной для погоды, не мешать читать данные, закрывать весь экран и **не меняться** при переключении вкладок. Главная идея: фон рисуется **один раз, на самом верху приложения**, а всё остальное лежит поверх. Новые темы: **ассеты**, **`MaterialApp.builder`**, **`Stack` и `BoxFit.cover`**, **градиент-подложка**, **«стекло»** для читаемости, **декодирование картинки и память**.

> **Честная пометка о проверке.** Код модуля 03 написан **без запуска** (в среде подготовки нет Flutter SDK). Синтаксис Dart проверен парсером, но `flutter analyze`, `flutter test` и вид на телефоне ещё никто не видел. Особенно это касается **загрузки картинки в тестах** (раздел 7) и **того, как фон выглядит**. Смотрите приложение глазами (раздел 6).

## 1. Задача и с чего начать

### 1.1 Условия сабжа

- **Общее:** проект копируется в новую папку (см. [03-ex00, раздел 1.7](03-ex00.md#17-как-начать-модуль-копирование-проекта)); дизайн свободный.
- **Папка сдачи:** `mobileModule03`; **файлы:** `advanced_weather_app` и всё необходимое (включая картинку в `assets/`).
- **Требования ex01:**
  - **фоновое изображение**, подходящее для погодного приложения;
  - оно **не должно мешать** видеть информацию;
  - занимает **весь экран**;
  - **остаётся неизменным при переключении вкладок**;
  - присутствует **один раз, в основе приложения** (не «на каждой вкладке своя копия»).

### 1.2 Проблема

Простое решение «положить картинку в `Scaffold` каждой вкладки» нарушает сразу два пункта: картинок станет три (по числу вкладок), и при свайпе они будут **ездить вместе с вкладкой**: вы увидите, как фон «уезжает» вбок. Это «лишнее» и по сабжу, и по ощущению.

### 1.3 Требования

**Функциональные:** одна картинка на весь экран (в том числе за статус-баром и жестовой панелью); не двигается и не мигает при смене вкладок, поиске, ошибке; интерфейс читается поверх неё.

**Нефункциональные:**

- **Читаемость:** контраст белого текста с фоном под ним не ниже 4,5:1 **в худшем месте картинки**.
- **Производительность:** картинка небольшая (десятки килобайт), не тормозит прокрутку.
- **Надёжность:** если файл картинки потерялся, приложение не «падает» и остаётся читаемым.
- **Лицензия:** картинку можно законно хранить в репозитории и сдавать.

### 1.4 Что не входит в задачу (non-goals)

- Смена фона в зависимости от погоды или времени суток (хорошая идея «на потом»).
- Размытие фона (`BackdropFilter`) и параллакс.
- Анимации.
- Разные картинки для телефона и планшета.

### 1.5 Критерии успеха

- [ ] Картинка есть и она **похожа на небо** (уместна).
- [ ] Закрывает весь экран на любом размере окна, включая ландшафт.
- [ ] Свайп вкладок: фон **стоит на месте**.
- [ ] В коде виджет фона создаётся **один раз** (`MaterialApp.builder`).
- [ ] Весь текст читается в любом месте экрана.
- [ ] Удаление файла картинки не ломает приложение (остаётся однотонный синий).
- [ ] Тесты зелёные (или, по крайней мере, понятно, почему нет: раздел 7).

### 1.6 Первый шаг (spike)

Дешёвый эксперимент до всякого кода: в `home_page.dart` старого проекта временно заменить `backgroundColor` `Scaffold` на `Image.asset(...)` в `body: Stack(...)` и прокрутить вкладки. Вы увидите ровно проблему из 1.2: фон уезжает со вкладкой (и дублируется). Это доказывает, зачем нужен единый слой над навигацией. Затем откатить и делать правильно.

## 2. Теория

### 2.1 Словарик (простыми словами)

| Слово | Что это |
|---|---|
| **Ассет (asset)** | Файл, который «зашит» в приложение: картинка, шрифт, звук. Лежит в папке проекта, например `assets/images/`. |
| **`pubspec.yaml`, раздел `assets`** | Список файлов-ассетов. Если файла там нет, `Image.asset` его не найдёт, даже если он лежит на диске. |
| **`Image.asset`** | Виджет, который показывает картинку из ассетов. |
| **`BoxFit.cover`** | «Заполни всю область, сохраняя пропорции, а лишнее обрежь». Как `background-size: cover` в CSS. |
| **Пропорции (aspect ratio)** | Отношение ширины к высоте. У картинки 1080×1920 это 9:16. |
| **`Stack`** | Виджет, который кладёт детей друг на друга слоями (первый ребёнок внизу). |
| **`StackFit.expand`** | Заставляет детей `Stack` занять **всю** его область. |
| **`MaterialApp.builder`** | Функция, которая оборачивает **всё** приложение (все экраны) один раз. Сюда кладут то, что должно быть «общим». |
| **`Navigator`** | Служба, которая показывает экраны и переключает между ними. |
| **Градиент** | Плавный переход цвета. `LinearGradient`: по прямой, например сверху вниз. |
| **Подложка (scrim)** | Полупрозрачный тёмный слой между картинкой и текстом, чтобы текст читался. |
| **«Стекло» (glass)** | Наша плашка `GlassCard`: 40% чёрного + тонкая светлая рамка. Фон через неё виден, но темнее. |
| **Декодирование** | Превращение сжатого файла (JPEG) в массив пикселей в памяти. Занимает память: ширина × высота × 4 байта. |
| **`errorBuilder`** | Что показать, если картинку загрузить не удалось. |
| **`Semantics`** | Описание виджета для скринридера (озвучка для слабовидящих). |
| **`excludeFromSemantics`** | «Скринридеру эту картинку не зачитывать»: она только украшение. |
| **JPEG** | Формат картинок со сжатием с потерями: маленький файл, подходит для фотографий и градиентов. |
| **Сид (seed) генератора** | Число, которое фиксирует «случайность»: с тем же сидом получается та же картинка. |

### 2.2 Где в Flutter «верх» приложения

Дерево виджетов приложения упрощённо выглядит так:

```text
MaterialApp
 └─ (builder)  ← сюда можно вставить обёртку над всем
     └─ Navigator
         └─ HomePage → Scaffold → TabBarView → вкладки...
```

Если фон положить **внутрь вкладки**, он живёт и умирает вместе с ней. Если положить в `Scaffold` страницы, он принадлежит этой странице (а при втором экране не будет вообще). Но `MaterialApp.builder` вызывается один раз и **выше навигатора**: вставленное туда живёт, пока живёт приложение, и не затрагивается ни свайпами вкладок, ни переходами между экранами.

### 2.3 Как работает `Stack` с `StackFit.expand`

```dart
Stack(
  fit: StackFit.expand,                 // каждый ребёнок растягивается на весь Stack
  children: [
    Image.asset(...),                   // слой 1 (внизу): картинка
    DecoratedBox(gradient...),          // слой 2: тёмная подложка
    child,                              // слой 3 (сверху): всё приложение
  ],
)
```

Дети рисуются **по порядку**: последний сверху. `StackFit.expand` даёт каждому ограничения «ровно такой размер, как у `Stack`». Сам `Stack` внутри `MaterialApp` получает размер **всего экрана**, поэтому и картинка, и приложение получают размер всего экрана.

### 2.4 `BoxFit.cover` на простых числах

Экран 390×844 (отношение 0,462), картинка 1080×1920 (отношение 0,5625). Картинка **шире** экрана по пропорции, значит:

1. Масштабируем так, чтобы заполнить **высоту**: коэффициент `844 / 1920 = 0,4396`; ширина становится `1080 × 0,4396 = 474,8`.
2. 474,8 больше 390, значит по бокам лишние `(474,8 − 390) / 2 = 42,4` пикселя с каждой стороны **обрезаются**.

А на широком экране (1200×600, отношение 2) картинка масштабируется по **ширине** (`1200 / 1080 = 1,11`, высота 2133), и обрезаются верх и низ. Пустых полос не бывает никогда: это и значит «cover». Альтернативы: `BoxFit.fill` растягивает и искажает; `BoxFit.contain` оставляет пустые полосы по краям.

Следствие для дизайна: **важное на картинке не держать у самого края**, оно может обрезаться. Поэтому наше «свечение у горизонта» чуть правее центра, а не в углу.

### 2.5 Читаемость текста поверх картинки

На картинке есть и тёмные, и светлые места. Белый текст читается только там, где фон достаточно тёмный. Мы применяем **два слоя защиты**:

1. **Подложка-градиент** (`AppBackground`): общее затемнение 20-60% (сверху и снизу сильнее: там поле поиска и панель вкладок).
2. **«Стекло»** (`GlassCard`) под любым блоком текста: ещё 40% чёрного.

Расчёт по **всем пикселям** сгенерированной картинки: контраст белого текста против цвета фона в точке (формула WCAG), для трёх вариантов:

| Условие | Худшая точка | Медиана | Оценка |
|---|---|---|---|
| Белый текст прямо на картинке, без слоёв | **1,03:1** | 4,7:1 | у горизонта текст вообще не виден |
| + подложка-градиент (`AppBackground`) | **3,10:1** | 7,4:1 | в худшей точке не проходит AA (4,5) |
| + «стекло» 40% чёрного (`GlassCard`) | **7,14:1** | 12,6:1 | проходит даже AAA (7) |

Вывод: подложка нужна, но **главная защита это «стекло» под текстом**. Подложка делает фон приятным, стекло делает текст читаемым.

> Цифры получены расчётом по пикселям файла `background.jpg` (подложка: 50% чёрного сверху, 20% в середине, 60% снизу, линейно между точками; стекло: ещё 40%). Это **расчёт, а не снимок экрана**: на телефоне дисплей другой, яркость другая. Но порядок величин (3 против 7) обоснованно говорит, что без стекла рисковать нельзя.

### 2.6 Ассеты: как картинка попадает в приложение

Три шага, и **все три нужны**:

1. Файл лежит в проекте: `assets/images/background.jpg`.
2. Он **объявлен** в `pubspec.yaml`:

   ```yaml
   flutter:
     assets:
       - assets/images/background.jpg
   ```

   (отступ в 2 пробела важен, YAML очень привередлив к пробелам и не принимает табы.)
3. После правки `pubspec.yaml`: `flutter pub get` (или перезапуск приложения: **hot reload ассеты не подхватывает**).

Если пропустить шаг 2, `Image.asset` бросает исключение `Unable to load asset`, а `errorBuilder` покажет запасной цвет.

### 2.7 Память: сколько «весит» картинка на самом деле

Файл JPEG 45 КБ, но в памяти картинка **разжимается** в пиксели: `1080 × 1920 × 4 байта = 8,3 МБ`. Это допустимо: один раз, одна картинка. Но если бы вы положили 4К-фото 3840×2160 (33 МБ в памяти) на каждую вкладку, телефон со слабой памятью начал бы убивать приложение. Правила:

- Размер картинки не больше разрешения экрана (1080×1920 хватает любому телефону).
- Картинка **одна**.
- Для больших ассетов `Image.asset(..., cacheWidth: 1080)` просит декодер сразу уменьшить.

### 2.8 Лицензия картинки

Картинку нельзя просто «скачать из интернета»: у каждой есть автор и условия. Чтобы не зависеть от этого, мы **нарисовали фон кодом**, скрипт [`tools/make_background.py`](../tools/make_background.py): градиент неба, свечение у горизонта, облака из шума. У такой картинки нет автора, поэтому и лицензионных ограничений нет; скрипт воспроизводит её байт в байт (фиксированный сид 7).

Если вы захотите **заменить** картинку на фотографию, проверьте лицензию (Unsplash, Pexels и Pixabay дают свободное использование, но читайте условия) и держите ссылку на источник в `README`.

## 3. Декомпозиция и решения

Части: **(а)** файл картинки и `pubspec.yaml`; **(б)** виджет `AppBackground`; **(в)** подключение в `MaterialApp.builder`; **(г)** прозрачные `Scaffold` и `AppBar`; **(д)** `GlassCard` и полупрозрачная нижняя панель; **(е)** тесты.

### Решение 1: фон один, в `MaterialApp.builder`

- **Варианты:** (а) `MaterialApp.builder`; (б) картинка в `Scaffold` каждой вкладки; (в) один `Stack` в `HomePage` под `TabBarView`; (г) `Container(decoration: DecorationImage)` в `Scaffold.body`.
- **Выбрано:** (а).
- **Почему:** это буквально «один раз в основе приложения» из сабжа, и фон не зависит от того, какие экраны появятся потом (второй экран, диалог, SnackBar поверх всего). (б) нарушает «один раз» и «не меняется». (в) допустим для одной страницы, но фон пропадёт на любом другом экране.
- **Что теряем / риски:** `builder` менее известен новичкам; нужно помнить, что `child` может быть `null` (в этой точке теоретически), поэтому `child ?? const SizedBox.shrink()`.

### Решение 2: подложка: градиент «темнее по краям»

- **Варианты:** (а) вертикальный градиент `0x80 → 0x33 → 0x99`; (б) ровное затемнение 40%; (в) без подложки.
- **Выбрано:** (а).
- **Почему:** сверху стоит поле поиска, снизу панель вкладок: там нужна тёмная опора. В середине хочется оставить картинку живее. Ровное затемнение (б) делает картинку «грязной» везде.
- **Что теряем / риски:** три числа подобраны на глаз и расчётом, на другой картинке их придётся подкручивать.

### Решение 3: «стекло» под текстом

- **Варианты:** (а) полупрозрачная чёрная плашка с рамкой; (б) белая плашка и тёмный текст; (в) `BackdropFilter` (размытие того, что под плашкой); (г) тень у текста.
- **Выбрано:** (а).
- **Почему:** гарантирует контраст 7:1 (раздел 2.5), стоит дёшево. (в) выглядит красиво, но `BackdropFilter` **дорог** для видеокарты, особенно на списках; (б) тяжело смотрится на тёмной теме; (г) тень не спасает на светлом пятне.
- **Что теряем / риски:** плашки могут «заслонять» картинку; 40% подобраны так, чтобы фон оставался виден.

### Решение 4: `Scaffold` и `AppBar` прозрачные

`Scaffold(backgroundColor: Colors.transparent)` и прозрачная панель из ex00. Иначе страница красит экран своим цветом **поверх** фона, и картинка исчезает. Это самая частая ошибка с «фоном под Scaffold».

### Решение 5: `errorBuilder` и сплошной цвет

Если картинку не нашли (опечатка в пути, забыли `pubspec`), приложение показывает однотонный `0xFF1B3A5C`: тёмно-синий, на нём белый текст читается. Без `errorBuilder` пользователь увидел бы красный экран ошибки или (в релизе) серый.

### Решение 6: картинка сгенерирована скриптом

- **Варианты:** (а) нарисовать кодом; (б) фото с бесплатного стока; (в) `Container` с градиентом без картинки.
- **Выбрано:** (а).
- **Почему:** нулевой риск по лицензии, воспроизводимость, крошечный файл (45 КБ), уместность (закатное небо). (в) не «изображение» и сабж явно просит «background image».
- **Что теряем / риски:** облака из шума выглядят менее «живыми», чем фото. Заменить на фото можно, поменяв один файл и сохранив имя.

### Решение 7: картинка вертикальная 1080×1920

Телефоны почти всегда стоят вертикально, и с `BoxFit.cover` вертикальная картинка на широком окне обрезается сверху и снизу, а небо остаётся небом. Для планшетов потом можно добавить вторую картинку.

### Решение 8: фон помечен `excludeFromSemantics`

Скринридер не должен произносить «изображение» на каждом экране. Это украшение, не информация.

#### Слой 2: ассет и `pubspec.yaml`

Картинка создаётся скриптом (из корня репозитория, нужны `Pillow` и `numpy`):

```bash

# -> mobileModule03/advanced_weather_app/assets/images/background.jpg
```

Скрипт целиком:

```python
#!/usr/bin/env python3
"""Генерирует фон приложения advanced_weather_app (закатное небо с облаками).

Зачем скрипт: картинка нарисована кодом, поэтому у неё нет автора и лицензии,
и её можно воспроизвести или поменять (цвета, облака, размер).
Запуск (нужны Pillow и numpy):
    python3 tools/make_background.py [выходной_файл]
По умолчанию пишет mobileModule03/advanced_weather_app/assets/images/background.jpg.
"""
import sys
import numpy as np
from PIL import Image, ImageFilter

OUT = sys.argv[1] if len(sys.argv) > 1 else \
    "mobileModule03/advanced_weather_app/assets/images/background.jpg"
W, H = 1080, 1920
rng = np.random.default_rng(7)  # фиксированное зерно: результат всегда одинаковый


def lerp(a, b, t):
    return a + (b - a) * t


y = np.linspace(0, 1, H)[:, None]
top = np.array([14, 32, 74])
mid = np.array([52, 98, 150])
low = np.array([236, 150, 110])
hor = np.array([250, 205, 150])

t1 = np.clip(y / 0.55, 0, 1)
t2 = np.clip((y - 0.55) / 0.30, 0, 1)
t3 = np.clip((y - 0.85) / 0.15, 0, 1)
base = lerp(top, mid, t1[..., None])
base = lerp(base, low, t2[..., None] * (y[..., None] > 0.55))
base = lerp(base, hor, t3[..., None] * (y[..., None] > 0.85))
img = np.zeros((H, W, 3))
img[:] = base

# свечение у горизонта
yy, xx = np.mgrid[0:H, 0:W]
d = np.sqrt((xx - W * 0.72) ** 2 + (yy - H * 0.80) ** 2)
img = img + np.exp(-(d / 380) ** 2)[..., None] * np.array([255, 214, 160]) * 0.55


def noise(scale):
    small = rng.random((H // scale + 2, W // scale + 2))
    resized = Image.fromarray((small * 255).astype(np.uint8)).resize((W, H), Image.BICUBIC)
    return np.asarray(resized, dtype=float) / 255


# облака: шум из трёх масштабов, больше всего в середине неба
n = 0.55 * noise(300) + 0.3 * noise(120) + 0.15 * noise(50)
mask = np.clip((n - 0.52) * 4.0, 0, 1) * np.exp(-((y - 0.45) / 0.28) ** 2)
mask = mask[..., None]
cloud = np.array([255, 236, 224]) * 0.9 + img * 0.1
img = img * (1 - 0.55 * mask) + cloud * (0.55 * mask)

Image.fromarray(np.clip(img, 0, 255).astype(np.uint8)) \
    .filter(ImageFilter.GaussianBlur(1.2)) \
    .save(OUT, quality=82, optimize=True)
print("записано:", OUT)
```

Разбор скрипта:

- `rng = np.random.default_rng(7)`: фиксированный сид, поэтому картинка всегда одинаковая.
- `base`: четыре цвета неба (`top` тёмно-синий, `mid` голубой, `low` оранжево-розовый, `hor` светло-персиковый у горизонта) смешиваются по высоте `y` (от 0 до 1). `np.clip` ограничивает долю смешивания в нужных отрезках неба: 0-55%, 55-85% и 85-100% высоты.
- `exp(-(d / 380) ** 2)`: колоколообразное **свечение** (гауссиана) вокруг точки правее центра ближе к низу: расстояние `d` от точки, чем дальше, тем слабее.
- `noise(scale)`: случайные значения на мелкой сетке, растянутые `BICUBIC`-интерполяцией до размера картинки: получается гладкий шум. Три масштаба (300, 120, 50 пикселей) в пропорции 55/30/15 дают «крупные облака с мелкой рябью».
- `mask`: где шум больше порога 0,52, там облако; умножение на `exp(-((y - 0.45) / 0.28) ** 2)` оставляет облака в **середине** неба.
- Облако смешивается с небом на 55%. `GaussianBlur(1.2)` чуть размывает: убирает зернистость. `quality=82` и `optimize=True` даёт 45 КБ.

#### Слой 3: виджет `AppBackground`

**`lib/ui/app_background.dart`**:

```dart
import 'package:material_ui/material_ui.dart';

// Путь к картинке фона (она объявлена в pubspec.yaml, раздел assets).
const String backgroundAsset = 'assets/images/background.jpg';

// Фон приложения. Создаётся ОДИН раз, в MaterialApp.builder, то есть ВЫШЕ
// навигатора и всех экранов: вкладки, поиск, ошибки лежат поверх него,
// а он не перерисовывается и не дублируется (требование сабжа).
//
// Слои снизу вверх:
//   1. картинка на весь экран (BoxFit.cover: заполняет, обрезая лишнее по краям);
//   2. тёмный градиент: чуть темнее сверху (под полем поиска) и снизу (под панелью
//      вкладок), чтобы светлый текст читался на любом куске картинки;
//   3. сам интерфейс (child).
class AppBackground extends StatelessWidget {
  const AppBackground({super.key, required this.child});

  final Widget child;

  @override
  Widget build(BuildContext context) {
    return Stack(
      fit: StackFit.expand,
      children: [
        Image.asset(
          backgroundAsset,
          fit: BoxFit.cover,
          excludeFromSemantics: true, // декоративная: скринридеру она не нужна
          // Если файл потерялся, приложение остаётся читаемым на сплошном цвете.
          errorBuilder: (BuildContext context, Object error, StackTrace? stack) =>
              const ColoredBox(color: Color(0xFF1B3A5C)),
        ),
        const DecoratedBox(
          decoration: BoxDecoration(
            gradient: LinearGradient(
              begin: Alignment.topCenter,
              end: Alignment.bottomCenter,
              colors: [Color(0x80000000), Color(0x33000000), Color(0x99000000)],
            ),
          ),
        ),
        child,
      ],
    );
  }
}
```

Разбор:

- `const String backgroundAsset = ...`: путь в **одном** месте; его же использует тест.
- `class AppBackground extends StatelessWidget`: без состояния, фон не меняется.
- `Stack(fit: StackFit.expand, ...)`: раздел 2.3.
- `Image.asset(backgroundAsset, fit: BoxFit.cover, ...)`: раздел 2.4.
- `excludeFromSemantics: true`: решение 8.
- `errorBuilder: (context, error, stack) => const ColoredBox(...)`: решение 5. Три параметра: контекст, ошибка и стек (нам не нужны).
- `const DecoratedBox(decoration: BoxDecoration(gradient: LinearGradient(...)))`: подложка. `begin: topCenter`, `end: bottomCenter` значит сверху вниз; три цвета равномерно: `0x80000000` (50% чёрного) → `0x33000000` (20%) → `0x99000000` (60%).
- `child`: всё приложение сверху.

#### Слой 5: «стекло» и прозрачные поверхности

**`lib/ui/glass_card.dart`**:

```dart
import 'package:material_ui/material_ui.dart';

// «Стекло»: полупрозрачная тёмная плашка. Через неё виден фон (мы его видим и
// понимаем, где находимся), а текст на ней читается на любой картинке:
// темнее фон под текстом = выше контраст.
//
// Цвет 0x66 = 40% непрозрачности чёрного (0x66 / 0xFF).
const Color glassColor = Color(0x66000000);

class GlassCard extends StatelessWidget {
  const GlassCard({
    super.key,
    required this.child,
    this.padding = const EdgeInsets.all(16),
    this.margin = EdgeInsets.zero,
    this.radius = 20,
  });

  final Widget child;
  final EdgeInsetsGeometry padding;
  final EdgeInsetsGeometry margin;
  final double radius;

  @override
  Widget build(BuildContext context) {
    return Container(
      margin: margin,
      padding: padding,
      decoration: BoxDecoration(
        color: glassColor,
        borderRadius: BorderRadius.circular(radius),
        border: Border.all(color: const Color(0x33FFFFFF)), // тонкая светлая кромка
      ),
      child: child,
    );
  }
}
```

- `const Color glassColor = Color(0x66000000)`: `0x66 = 102`, `102 / 255 = 0,4`, то есть 40%.
- `Container(margin, padding, decoration: BoxDecoration(color, borderRadius, border))`: закруглённая плашка с тонкой светлой рамкой `0x33FFFFFF` (20% белого): отделяет плашку от фона, даже если он тёмный.

В `HomePage`: `Scaffold(backgroundColor: Colors.transparent)` и нижняя панель:

```dart
bottomNavigationBar: BottomAppBar(
  color: glassColor,                        // полупрозрачная: фон виден и под ней
```

### 4.2 Итоговая схема слоёв

```text
┌─────────────────────────────────────────┐ ← весь экран
│ AppBackground (Stack, expand)           │
│  ├ 1. Image.asset (cover)       ▒▒▒▒▒▒  │
│  ├ 2. градиент-подложка         ░░░░░░  │
│  └ 3. Navigator → HomePage              │
│       Scaffold (transparent)            │
│        ├ AppBar (transparent): поле     │
│        ├ TabBarView: GlassCard c данными│
│        └ BottomAppBar (стекло): вкладки │
└─────────────────────────────────────────┘
```

### 4.3 Симуляция: свайп вкладки

| № | Что происходит | Фон |
|---|---|---|
| 1 | экран Currently: `TabBarView` показывает страницу 0 | `AppBackground` построен один раз |
| 2 | палец тянет влево | `TabBarView` двигает **страницы** (дети `Scaffold.body`) |
| 3 | страницы едут, `AppBackground` выше навигатора и **не участвует** | картинка стоит на месте |
| 4 | Today остановилась | `Element` фона тот же (`identical` = `true`) |
| 5 | пришло новое состояние погоды | `ListenableBuilder` перестраивает **вкладки**, не фон |

### 4.4 Симуляция: ошибка из-за забытого `transparent`

Если у `Scaffold` оставить цвет по умолчанию (тёмный `surface` темы, непрозрачный): `Scaffold` рисует **сплошной** прямоугольник на весь экран, фон под ним невидим. Приложение выглядит «чёрным», а тест «Scaffold прозрачный» красный: именно поэтому он есть.

### 4.5 Симуляция: картинки нет

Допустим, файл переименовали. `Image.asset` пытается загрузить путь, бросает исключение, вызывается `errorBuilder`, показывается `ColoredBox(0xFF1B3A5C)`. Приложение работает, текст на «стекле» читается, хотя красоты поменьше. В консоли будет сообщение `Unable to load asset: "assets/images/background.jpg"`. Тест на присутствие картинки (`AssetImage.assetName`) проверяет **путь**, не наличие файла: «нет файла» ловится глазами и консолью.

## 5. Альтернативы

| Подход | Суть | Плюсы | Минусы | Когда подойдёт |
|---|---|---|---|---|
| **`MaterialApp.builder` + `Stack`** (выбрано) | фон выше навигатора | один раз, везде | нужно знать про `builder` | наш случай |
| `Container(decoration: DecorationImage)` вместо `Image.asset` | картинка как декорация | меньше виджетов | сложнее `errorBuilder` (есть `onError`) | простой фон |
| Фон в `Scaffold` каждой вкладки | у каждой свой | просто | нарушает «один раз», дублирует, ездит при свайпе | не для нас |
| Один `Stack` в `HomePage` | фон под `TabBarView` | локально, без `builder` | фон пропадёт на втором экране | приложение из одной страницы |
| `ThemeData.scaffoldBackgroundColor` + картинка | только цвет | — | картинку не задаёт | сплошной фон |
| `BackdropFilter` (размытие) | «матовое стекло» | красивее | тяжело для GPU, особенно в списках | редкие плашки |
| Фото вместо генерации | настоящее небо | живее | лицензия, размер, нужна проверка читаемости | если дизайн важнее |
| Сетевая картинка (`Image.network`) | с сервера | можно менять без релиза | нужен интернет, кэш, права | динамический фон |
| Фон по погоде | солнце/дождь/ночь | очень красиво | много картинок и логики | «на потом» |
| `Image.asset(cacheWidth: 1080)` | декодирование в меньший размер | экономия памяти | нужен только для больших файлов | большие исходники |

## 7. Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| Фона нет, экран тёмный | `Scaffold` непрозрачный | `backgroundColor: Colors.transparent` у `Scaffold` и `AppBar` |
| `Unable to load asset: "assets/images/background.jpg"` | Файла нет, нет в `pubspec.yaml` или не сделан `pub get` | Проверить путь, раздел `assets`, `flutter pub get`, перезапуск (не hot reload) |
| `pubspec.yaml: Error on line N` | Табы или неверные отступы в YAML | Только пробелы; `assets:` на уровне `uses-material-design` |
| Фон «ездит» со вкладкой | Фон лежит внутри вкладки | Перенести в `MaterialApp.builder` |
| На экране две и больше картинок | Фон добавлен и в `builder`, и в страницу | Оставить только `builder` |
| Белые полосы по краям | `BoxFit.contain` вместо `cover`, или `Stack` без `StackFit.expand` | `fit: BoxFit.cover`, `StackFit.expand` |
| Картинка размыта | Мала для экрана | Сгенерировать 1080×1920 и больше |
| Приложение вылетает на слабом телефоне | Слишком большая картинка в памяти | Уменьшить исходник или `cacheWidth` |
| Текст не читается на светлом пятне | Нет «стекла» под этим текстом | Обернуть блок в `GlassCard` |
| `No Directionality widget found` | Фон поставлен выше `MaterialApp` | Класть только в `MaterialApp.builder` |
| Тест: `Unable to load asset` в `flutter test` | В тестовой сборке ассет не объявлен или тест запущен вне корня проекта | Запускать `flutter test` из папки проекта; проверить `pubspec.yaml` |
| Тест: `findsOneWidget` для `Image` падает с 2 | Появилась иконка-картинка, например `Image` внутри другого виджета | Искать конкретно `find.byType(AppBackground)` и `AssetImage` |

> **Про тесты с картинкой.** В `flutter test` ассеты загружаются из того же `pubspec.yaml`, поэтому сам тест должен проходить. Но реальную **расшифровку JPEG** тест-окружение выполняет не всегда как на устройстве, и это одно из мест, где без запуска я не могу ручаться за результат. Если тест падает с ошибкой кодека, а на телефоне всё нормально, скажите, поправим тесты (например, подставим пустой `AssetBundle`).

## 8. Безопасность и риски

- **Лицензия.** Чужую картинку без разрешения использовать нельзя (и сдавать на проверку, и публиковать). Сгенерированный фон от этого свободен.
- **Размер приложения.** Каждый ассет увеличивает установочный файл. 45 КБ ничто, фото в 5 МБ уже заметно.
- **Доступность.** Читаемость текста это не вкус, а доступность. Смотрите на 7,14:1 как на запас по прочности.
- **Не прячьте информацию.** Сабж прямо говорит: фон «не должен мешать видеть информацию». Если вы сомневаетесь, затемнить или нет, затемняйте.
- **Расчёт ≠ экран.** Контраст посчитан по цветам картинки. На дисплее с низкой яркостью на солнце даже 7:1 бывает тяжело читать: проверьте на улице.
- **Непроверенный код.** Это единственное упражнение, где тесты зависят от загрузки файла: возможны мелочи (раздел 7).

## 10. Что запомнить

**Dart / YAML:**

- В `pubspec.yaml` только пробелы; ассет нужно **объявить**, иначе `Image.asset` его не найдёт.
- После правки `pubspec.yaml`: `flutter pub get` и полный перезапуск (hot reload не хватит).
- `identical(a, b)` проверяет «это один и тот же объект», а не «равны по значению».

**Flutter:**

- `MaterialApp.builder` оборачивает всё приложение один раз: идеальное место для общего фона.
- `Stack(fit: StackFit.expand)`: слои растягиваются на всю область, последний ребёнок сверху.
- `BoxFit.cover` заполняет область без полос и обрезает лишнее по краям; `contain` оставляет полосы; `fill` искажает.
- `Scaffold` и `AppBar` по умолчанию **непрозрачные**: чтобы фон был виден, нужен `Colors.transparent`.
- `Image.asset(errorBuilder: ...)` не даёт приложению упасть без картинки; `excludeFromSemantics` убирает декор из озвучки.
- В памяти картинка весит `ширина × высота × 4` байта, а не размер файла.

**Дизайн:**

- Читаемость поверх картинки держится на **двух** слоях: общая подложка и «стекло» под текстом.
- Важное не держать у края картинки: `cover` его может обрезать.
- Фон должен быть фоном: если он перетягивает внимание на себя, затемняйте.
- Лицензия: либо своё, либо проверенный источник; генерация кодом снимает вопрос.
