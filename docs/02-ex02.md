# Модуль 02, ex02: Fill the Views

> Третье упражнение третьего модуля: три вкладки наконец показывают **настоящую погоду**. **Currently**: место, температура, описание и ветер. **Today**: список по часам. **Weekly**: прогноз на неделю с минимумом и максимумом. Один запрос к Open-Meteo кормит все три вкладки. Главные новые темы: **структура ответа прогноза** (колонки-массивы), **модели данных**, **разбор чужого JSON**, **коды погоды WMO**, **списки** (`ListView.builder`) и **«состояние → экран»** через `switch` по закрытым типам.

> **Честная пометка о проверке.** Как и в предыдущих разборах, код и тесты написаны **без запуска** (нет Flutter SDK, нет доступа к самим API). Форма ответа Open-Meteo взята из **документации**, а в тестах ответ собран вручную по ней. Реальный ответ проверьте командой `curl` из слоя 1 и, если он отличается, поправьте парсер вместе с тестом (и пришлите мне).

## 1. Задача и с чего начать

### 1.1 Условия сабжа

- **Папка сдачи:** `mobileModule02`, проект `medium_weather_app`
- **Запрещённые функции:** нет
- **Требования сабжа:**
  - **Currently:** местоположение (город, регион, страна), температура в °C, описание погоды (по коду), скорость ветра в км/ч;
  - **Today:** список по часам: время, температура, описание, ветер;
  - **Weekly:** по дням: дата, минимальная и максимальная температура, описание;
  - при запуске открыта **первая вкладка**; **новый поиск не меняет текущую вкладку**; при переключении вкладок везде показываются данные **последнего поиска**;
  - прогноз берётся из **Open-Meteo**; расшифровку кодов погоды приложение делает **само**.

### 1.2 Проблема

От одного запроса к API нужно получить данные для трёх разных видов («сейчас», «по часам сегодня», «по дням на неделю»), привести их к удобным для интерфейса структурам, показать, при этом:

- **не перепутать** единицы (°C и км/ч, а не °F и миль/ч);
- **не показать** чужой «сегодня»: для Токио и для Барселоны это разные календарные дни;
- пережить **странный ответ** (нет поля, `null`, целое число вместо дробного);
- не потерять **выбранную вкладку** при загрузке новых данных.

### 1.3 Требования

**Функциональные:**

- **Currently:** `Barcelona` / `Catalonia, Spain` / `12.3°C` / `Partly cloudy` / `Wind: 10.5 km/h`.
- **Today:** 24 строки (00:00...23:00), в каждой время + описание, ветер, температура справа.
- **Weekly:** 7 строк: дата, `min`/`max`, описание.
- Название места видно **на каждой** вкладке над данными.
- Пока данные грузятся: индикатор; после: данные; при ошибке: сообщение (ex03).

**Нефункциональные:**

- Один HTTP-запрос на обновление (а не три).
- Списки **прокручиваются** и не дают overflow на низком экране и крупном шрифте.
- Разбор данных проверен тестами без сети.
- Новая вкладка/дни/часы не требуют правок в сервисе: чистые функции форматирования отдельно.

### 1.4 Что не входит в задачу (non-goals)

- Иконки погоды, графики, фон по погоде (можно добавить: `weather_code` уже в модели).
- Локализованные даты («сб, 28 ноября»): нужен пакет `intl` (следующий модуль), мы показываем ISO `2026-11-28`.
- Кэш последнего ответа на диске, офлайн-режим.
- Обновление «потянуть вниз» (`RefreshIndicator`), автообновление по таймеру.
- Единицы по выбору пользователя (°F, mph).

### 1.5 Критерии успеха

- [ ] Выбрали город: на **Currently** название, температура, описание и ветер.
- [ ] **Today**: 24 строки, список прокручивается; **Weekly**: 7 строк.
- [ ] Свайп/нажатие по вкладкам: везде данные одного и того же города.
- [ ] Новый поиск на вкладке **Weekly** оставляет пользователя на **Weekly**.
- [ ] Поворот экрана, крупный шрифт: нет жёлто-чёрных полос overflow.
- [ ] Тесты сервиса, форматирования и экрана зелёные.

### 1.6 Первый шаг (spike)

Снова сначала **посмотреть на данные**. Подставьте координаты Барселоны:

```bash
curl -s 'https://api.open-meteo.com/v1/forecast?latitude=41.39&longitude=2.16&current=temperature_2m,weather_code,wind_speed_10m&hourly=temperature_2m,weather_code,wind_speed_10m&daily=weather_code,temperature_2m_max,temperature_2m_min&timezone=auto&forecast_days=7' | head -c 1800
```

Структура ответа (сокращённо, значения условные):

```json
{
  "latitude": 41.4, "longitude": 2.16, "timezone": "Europe/Madrid", ...
  "current": {
    "time": "2026-11-28T14:15", "interval": 900,
    "temperature_2m": 12.3, "weather_code": 2, "wind_speed_10m": 10.5
  },
  "hourly": {
    "time":           ["2026-11-28T00:00", "2026-11-28T01:00", ... 168 штук],
    "temperature_2m": [8.1, 7.9, ...],
    "weather_code":   [3, 3, ...],
    "wind_speed_10m": [4.2, 4.0, ...]
  },
  "daily": {
    "time":               ["2026-11-28", "2026-11-29", ... 7 штук],
    "weather_code":       [2, 61, ...],
    "temperature_2m_max": [14.0, 13.1, ...],
    "temperature_2m_min": [6.5, 7.0, ...]
  }
}
```

Что здесь важно (и это определяет весь код):

1. **Колонки, а не строки.** `hourly` и `daily` это не список объектов «час → значения», а **несколько параллельных массивов**: i-й элемент каждого массива относится к одному и тому же моменту. Объекты «один час» мы собираем сами по индексу.
2. **Часов не 24, а 168** (7 суток × 24): по умолчанию в `hourly` приходит вся неделя. «Сегодня» вырезаем сами.
3. **Время без пояса:** `"2026-11-28T14:15"`: это **местное время того места**, для которого запрошен прогноз (из-за `timezone=auto`).
4. **`current.time`** это «сейчас **там**». По нему определяем «сегодня».

## 2. Теория

### 2.1 Open-Meteo Forecast API: что мы просим

Запрос: `GET https://api.open-meteo.com/v1/forecast` с параметрами:

| Параметр | Значение | Зачем |
|---|---|---|
| `latitude`, `longitude` | из `Place` | где |
| `current` | `temperature_2m,weather_code,wind_speed_10m` | «сейчас» |
| `hourly` | те же три переменные | по часам |
| `daily` | `weather_code,temperature_2m_max,temperature_2m_min` | по дням |
| `timezone` | `auto` | пояс определяется по координатам (**для `daily` параметр обязателен**) |
| `forecast_days` | `7` | неделя (по умолчанию тоже 7, максимум 16) |
| `temperature_unit` | `celsius` | °C (и так по умолчанию, но явное лучше неявного) |
| `wind_speed_unit` | `kmh` | км/ч (то же) |

Переменные: `temperature_2m` температура на высоте 2 м, `wind_speed_10m` скорость ветра на высоте 10 м, `weather_code` код погоды **WMO**.

Параметр `current` это современный способ получить «сейчас». Старый `current_weather=true` ещё работает, но считается устаревшим и даёт меньше полей; новым проектам его не берут.

### 2.2 Коды погоды WMO

`weather_code` это число из таблицы Всемирной метеорологической организации. Open-Meteo использует часть кодов:

| Код | Описание | Код | Описание |
|---|---|---|---|
| 0 | Clear sky | 71, 73, 75 | Slight / Moderate / Heavy snowfall |
| 1, 2, 3 | Mainly clear / Partly cloudy / Overcast | 77 | Snow grains |
| 45, 48 | Fog / Depositing rime fog | 80, 81, 82 | Slight / Moderate / Violent rain showers |
| 51, 53, 55 | Light / Moderate / Dense drizzle | 85, 86 | Slight / Heavy snow showers |
| 56, 57 | Light / Dense freezing drizzle | 95 | Thunderstorm |
| 61, 63, 65 | Slight / Moderate / Heavy rain | 96, 99 | Thunderstorm with slight / heavy hail |
| 66, 67 | Light / Heavy freezing rain | 97 | Heavy thunderstorm |

По документации 96 и 99 (град) выдают только некоторые модели прогноза, остальные обходятся 95 и 97; мы поддерживаем все.

В Dart такая таблица естественно выглядит как **switch-выражение**:

```dart
String describeWeatherCode(int code) => switch (code) {
  0 => 'Clear sky',
  1 => 'Mainly clear',
  ...
  _ => 'Unknown weather',      // всё остальное
};
```

Отличие от оператора `switch`: это **выражение** (даёт значение), нет `case`/`break`, ветки `образец => результат`, а `_` ловит всё прочее. Код, которого нет в таблице (а его могут добавить завтра), не должен ронять экран: отсюда `'Unknown weather'`.

### 2.3 Модели данных

Мы превращаем «сырой» JSON (`Map`/`List`) в **типизированные неизменяемые объекты**:

```text
WeatherReport
 ├─ place: Place               (имя, регион, страна, координаты)
 ├─ current: CurrentWeather    (temperature, weatherCode, windSpeed)
 ├─ hourly: List<HourlyWeather>(time, temperature, weatherCode, windSpeed)  — только сегодня
 └─ daily: List<DailyWeather>  (date, min/maxTemperature, weatherCode)      — 7 дней
```

Выгоды: (1) опечатка в имени поля ловится **компилятором**, а не падением на экране; (2) всё «грязное» (`as`, `num`, `DateTime.parse`) собрано в **одном** файле (`weather_service.dart`); (3) виджеты работают с чистыми данными и легко тестируются «руками собранным» отчётом (`sampleReport`).

### 2.4 Даты и «сегодня»

`DateTime.parse('2026-11-28T14:15')` без указания пояса даёт `DateTime` в **локальном часовом поясе телефона** с этими числами (год, месяц, день, час). Для нас важны именно **числа на часах того города**, поэтому:

- мы **не** превращаем время в UTC и **не** сравниваем с `DateTime.now()`: часы телефона (Барселона) и часы города (Токио) расходятся, и «сегодня» бы не совпало;
- «сегодня» это **дата из `current.time`**: берём те значения `hourly`, у которых совпадают год, месяц и день с ним.

Пограничный случай: перевод часов. Документация Open-Meteo честно предупреждает, что смена зимнего/летнего времени внутри запрошенного периода **игнорируется** (рекомендуют `timeformat=unixtime` для точной работы); для списка «24 часа сегодня» нам этого достаточно.

### 2.5 Списки: `ListView.builder`

```dart
ListView.builder(
  itemCount: hours.length + 1,                 // +1: нулевой элемент это заголовок
  itemBuilder: (BuildContext context, int index) {
    if (index == 0) return Padding(...);      // заголовок с названием города
    final HourlyWeather hour = hours[index - 1];
    return ListTile(...);
  },
)
```

- **`builder`**: список строит строки **лениво**, только те, что видны. Для 24 и 7 строк разницы нет, но привычка правильная.
- **Заголовок как нулевой элемент того же списка** (а не отдельный виджет над ним): тогда прокручивается всё вместе. Иначе на низком экране (ландшафт, 280 px высоты) заголовок и список в `Column` дали бы overflow, или пришлось бы оборачивать список в `Expanded`.
- **`ListTile`**: готовая строка Material: `title`, `subtitle`, `trailing`.

### 2.6 Состояние, вкладки и `switch` по закрытым типам

`TabPage` получает **вкладку** и **состояние** и возвращает виджет. Два вложенных `switch` по закрытым типам:

```dart
switch (state) {
  WeatherIdle()                  => const SizedBox.shrink(),
  WeatherLoading()               => const Center(child: CircularProgressIndicator()),
  WeatherFailed(:final failure)  => MessageView(failure: failure),
  WeatherLoaded(:final report)   => switch (tab) {
    WeatherTab.currently => CurrentView(report: report),
    WeatherTab.today     => TodayView(report: report),
    WeatherTab.weekly    => WeeklyView(report: report),
  },
}
```

- **Образец объекта** (object pattern) `WeatherLoaded(:final report)`: проверяет тип **и** достаёт поле в одну переменную.
- **Полнота.** И `WeatherState` (sealed), и `WeatherTab` (enum) закрыты. Добавите четвёртое состояние или вкладку, и код **не соберётся**, пока вы не обработаете их везде. Это главная выгода «закрытых» типов.

### 2.7 Почему вкладка не сбрасывается

Выбранная вкладка хранится в `TabController`, который создаёт `DefaultTabController`. В нашем дереве он стоит **выше** `ListenableBuilder`, который перестраивается при каждом изменении состояния:

```text
DefaultTabController        ← хозяин индекса вкладки (не перестраивается)
 └─ Scaffold
     └─ ListenableBuilder   ← перестраивается при каждом notifyListeners
         └─ Stack → TabBarView → TabPage(tab, state) × 3
```

Данные меняются, перестраиваются **страницы**, а индекс вкладки живёт выше, значит, он прежний. Именно это выполняет требование «поиск не меняет вкладку». Если бы `DefaultTabController` оказался **внутри** `ListenableBuilder`, он создавался бы заново, и вкладка сбрасывалась на первую (классическая ошибка).

Требование «при переключении вкладок везде данные последнего поиска» выполняется тем, что **данные хранятся не во вкладках, а в контроллере**: все три страницы читают одно и то же `state`.

## 3. Декомпозиция и решения

Части: **(а)** модели; **(б)** `WeatherService` (запрос и разбор); **(в)** расшифровка кодов; **(г)** форматирование чисел и дат; **(д)** три вида вкладок и шапка места; **(е)** `TabPage`: сопоставление состояния и вида; **(ж)** тесты.

### Решение 1: один запрос на все вкладки

- **Варианты:** (а) один запрос, один `WeatherReport` на три вкладки; (б) по запросу на вкладку (лениво, при открытии); (в) отдельные запросы за «current», «hourly», «daily».
- **Выбрано:** (а).
- **Почему:** Open-Meteo отдаёт `current`, `hourly` и `daily` **в одном ответе**; сабж требует, чтобы при переключении вкладок были данные последнего поиска, а не новая загрузка. Один запрос это одна точка отказа, один индикатор, согласованные данные (все из одного момента) и в три раза меньше нагрузки на лимит.
- **Что теряем / риски:** ответ чуть больше (168 часов, из которых мы показываем 24). Это килобайты.

### Решение 2: модели неизменяемые и свои

См. 2.3. Альтернатива: хранить `Map<String, dynamic>` и читать значения во view. Отвергнута: опечатки в строках-ключах всплывают только на устройстве.

### Решение 3: единицы запрашиваем явно

- **Выбрано:** `temperature_unit=celsius&wind_speed_unit=kmh` в запросе, несмотря на то что это значения по умолчанию.
- **Почему:** сабж требует °C и км/ч. Если API когда-нибудь поменяет умолчание, приложение не должно «тихо» начать показывать другое. Плюс запрос **документирует** намерение.

### Решение 4: «сегодня» по времени места

См. 2.4. **Выбрано:** фильтр по дате из `current.time`.

- **Альтернативы:** (а) `DateTime.now()` телефона; (б) первые 24 элемента `hourly`; (в) параметр запроса `forecast_hours`/`past_hours`.
- **Почему не они:** (а) неверно в другом часовом поясе, (б) при `timezone=auto` массив начинается с 00:00 **сегодняшней даты места**, так что (б) на практике совпадает с нашим фильтром, но завязано на недокументированном порядке; наш фильтр явный и проверяется тестом.

### Решение 5: заголовок внутри списка

См. 2.5.

### Решение 6: ISO-даты

- **Варианты:** (а) `2026-11-28`; (б) «Sat, 28 Nov» через `intl`; (в) ручной массив названий дней недели.
- **Выбрано:** (а).
- **Почему:** (б) добавляет пакет и локали (следующий модуль), (в) тащит свои ошибки (с какой недели начинать, какой язык). ISO однозначен и сортируем; сабж требует лишь «дату».
- **Что теряем / риски:** выглядит «технично». Заменяется одной функцией `formatDate`.

### Решение 7: форматирование отдельно от виджетов

`formatTemperature`, `formatWind`, `formatHour`, `formatDate` это **чистые функции** в `formatters.dart`. Так их проверяют обычные `test`, без экрана; а `'-0.0°C'` (так выглядит `-0.04`) превращается в `'0.0°C'`: тест это фиксирует.

### Решение 8: что показываем во время загрузки

- **Варианты:** (а) индикатор вместо данных; (б) оставить **старые данные** и показать тонкую полоску загрузки; (в) заглушки-«скелетоны».
- **Выбрано:** (а).
- **Почему:** проще и честно: пока нет новых данных, не показываем старые (иначе пользователь мог бы принять Париж за Рим). Требование сабжа лишь «показывать данные последнего поиска».
- **Что теряем / риски:** при каждом поиске данные «мигают» индикатором. Вариант (б) улучшает UX, но усложняет состояние (`Loading(previous)`).

### Решение 9: индикатор загрузки и тесты

Индикатор `CircularProgressIndicator` **не показываем в тестах через `pumpAndSettle`**: он анимируется бесконечно, и `pumpAndSettle` никогда не «успокоится» (бросит таймаут). Поэтому в тестах с загруженными данными можно `pumpAndSettle`, а во время загрузки: `pump` с явным временем (см. раздел тестов).

```dart
// Погода «сейчас»: температура в °C, ветер в км/ч (единицы мы просим у API явно).
class CurrentWeather {

    required this.temperature,

    required this.windSpeed,

  final int weatherCode;
  final double windSpeed;

    required this.temperature,
    required this.weatherCode,

  final DateTime time;

  const DailyWeather({
    required this.date,
    required this.minTemperature,
    required this.maxTemperature,
    required this.weatherCode,
  });

  final DateTime date;
  final double minTemperature;
  final double maxTemperature;
  final int weatherCode;

  String get description => describeWeatherCode(weatherCode);
}

// Всё, что нужно трём вкладкам, одним объектом: место + три среза погоды.
class WeatherReport {
  const WeatherReport({
    required this.place,
    required this.current,
    required this.hourly,
    required this.daily,
  });

  final Place place;
  final CurrentWeather current;
  final List<HourlyWeather> hourly; // только сегодня, до 24 записей
  final List<DailyWeather> daily; // до 7 дней
```

Разбор:

- Четыре класса, у каждого `const`-конструктор с **обязательными именованными** параметрами (`required this.x`): при создании видно, где какое поле.
- Все поля `final`: объекты **неизменяемы**; изменить погоду «по месту» нельзя, только заменить отчёт целиком.
- `String get description => describeWeatherCode(weatherCode);`: **вычисляемое свойство**: хранить текст не нужно, он выводится из кода.
- `windSpeed` и `temperature` это `double`: ответ даёт и целые, и дробные, мы приводим в сервисе.
- `HourlyWeather.time` хранит `DateTime` **местного времени города** (комментарий в коде).

#### Слой 3: `WeatherService`

**`lib/services/weather_service.dart`**:

```dart
import 'package:http/http.dart' as http;

import '../models/place.dart';
import '../models/weather_report.dart';
import 'http_json.dart';

// «Место => прогноз».
abstract interface class WeatherService {
  // Бросает ConnectionFailure или ServerFailure.
  Future<WeatherReport> fetch(Place place);
}

// Weather Forecast API от Open-Meteo: https://open-meteo.com/en/docs
final class OpenMeteoWeatherService implements WeatherService {
  OpenMeteoWeatherService(this._client);

  final http.Client _client;

  @override
  Future<WeatherReport> fetch(Place place) async {
    final Uri uri = Uri.https('api.open-meteo.com', '/v1/forecast', {
      'latitude': '${place.coordinates.latitude}',
      'longitude': '${place.coordinates.longitude}',
      'current': 'temperature_2m,weather_code,wind_speed_10m',
      'hourly': 'temperature_2m,weather_code,wind_speed_10m',
      'daily': 'weather_code,temperature_2m_max,temperature_2m_min',
      // auto: часовой пояс самого места. Без него daily не работает, а часы
      // были бы по Гринвичу.
      'timezone': 'auto',
      'forecast_days': '7',
      // По умолчанию и так °C и км/ч, но явное лучше неявного.
      'temperature_unit': 'celsius',
      'wind_speed_unit': 'kmh',
    });

    final Map<String, dynamic> json = await getJson(_client, uri);
    return parseResponse(() => _parse(place, json));
  }

  WeatherReport _parse(Place place, Map<String, dynamic> json) {
    // --- сейчас ---
    final Map<String, dynamic> current = json['current'] as Map<String, dynamic>;
    final DateTime now = DateTime.parse(current['time'] as String);

    // --- по часам: в ответе 7 суток подряд (168 значений), нам нужен «сегодня» ---
    final Map<String, dynamic> hourly = json['hourly'] as Map<String, dynamic>;
    final List<Object?> hourTimes = hourly['time'] as List<Object?>;
    final List<Object?> hourTemps = hourly['temperature_2m'] as List<Object?>;
    final List<Object?> hourCodes = hourly['weather_code'] as List<Object?>;
    final List<Object?> hourWinds = hourly['wind_speed_10m'] as List<Object?>;

    final List<HourlyWeather> today = [];
    for (int i = 0; i < hourTimes.length; i++) {
      final DateTime time = DateTime.parse(hourTimes[i] as String);
      // «Сегодня» определяем по ТЕКУЩЕМУ времени места (current.time),
      // а не по часам телефона: в Токио и в Барселоне «сегодня» разное.
      if (time.year == now.year && time.month == now.month && time.day == now.day) {
        today.add(
          HourlyWeather(
            time: time,
            temperature: _number(hourTemps[i]),
            weatherCode: _integer(hourCodes[i]),
            windSpeed: _number(hourWinds[i]),
          ),
        );
      }
    }

    // --- по дням ---
    final Map<String, dynamic> daily = json['daily'] as Map<String, dynamic>;
    final List<Object?> dayDates = daily['time'] as List<Object?>;
    final List<Object?> dayCodes = daily['weather_code'] as List<Object?>;
    final List<Object?> dayMax = daily['temperature_2m_max'] as List<Object?>;
    final List<Object?> dayMin = daily['temperature_2m_min'] as List<Object?>;

    return WeatherReport(
      place: place,
      current: CurrentWeather(
        temperature: _number(current['temperature_2m']),
        weatherCode: _integer(current['weather_code']),
        windSpeed: _number(current['wind_speed_10m']),
      ),
      hourly: today,
      daily: [
        for (int i = 0; i < dayDates.length; i++)
          DailyWeather(
            date: DateTime.parse(dayDates[i] as String),
            minTemperature: _number(dayMin[i]),
            maxTemperature: _number(dayMax[i]),
            weatherCode: _integer(dayCodes[i]),
          ),
      ],
    );
  }

  // JSON-число может прийти и как 12 (int), и как 12.5 (double): приводим через num.
  // null (нет данных) даст TypeError и станет ServerFailure.
  double _number(Object? value) => (value as num).toDouble();

  int _integer(Object? value) => (value as num).toInt();
}
```

Разбор сверху вниз:

1. **Интерфейс** `WeatherService.fetch(Place)`: контроллер зависит от него (подделка в тестах).
2. **Адрес запроса:** `Uri.https('api.open-meteo.com', '/v1/forecast', {...})`; значения словаря строковые, поэтому `'${place.coordinates.latitude}'`.
3. `getJson(...)`: общая часть из ex01 (сеть, коды, UTF-8). Потом `parseResponse(() => _parse(place, json))`: любое «не то» в форме JSON станет `ServerFailure`.
4. **`_parse`, блок «сейчас»:** `json['current'] as Map<String, dynamic>`: если блока нет, `TypeError` и `ServerFailure`. `now = DateTime.parse(current['time'] as String)`.
5. **Блок «по часам».** Достаём четыре параллельных массива (`List<Object?>`), потом **один цикл по индексу**: собираем `DateTime`, проверяем «тот же день, что `now`», и только тогда создаём `HourlyWeather`.
6. **Блок «по дням»:** четыре массива и `[for (int i = 0; i < dayDates.length; i++) DailyWeather(...)]`: **коллекция-цикл**: создаёт список выражением.
7. **`_number(Object?) => (value as num).toDouble()`**: ловушка `int`/`double`; `null` (нет данных на этот час) даёт `TypeError` и `ServerFailure`.

Что именно **не** делается и почему:

- Нет `try`/`catch` внутри `_parse`: единая обёртка снаружи.
- Нет проверки одинаковой длины массивов: при расхождении `RangeError` (тоже `Error`) превратится в `ServerFailure`. Разумно: если сервер прислал рассинхронизированные колонки, **лучше не показывать ничего, чем показать неверно**.
- Часы **не сортируются**: порядок задаёт сервер, и он хронологический.

#### Слой 4: форматирование

**`lib/ui/formatters.dart`**:

```dart
// Превращение чисел и дат в текст для экрана. Отдельно от виджетов, чтобы
// проверять тестами без интерфейса.

// «12.3°C». Округляем до десятых; «-0.0» (так выглядит -0.04) показываем как «0.0».
String formatTemperature(double value) => '${_oneDecimal(value)}°C';

// «10.5 km/h».
String formatWind(double value) => '${_oneDecimal(value)} km/h';

// «08:00».
String formatHour(DateTime time) => '${_two(time.hour)}:${_two(time.minute)}';

// «2026-11-28» (формат ISO: однозначный и сортируемый; красивые «Sat, 28 Nov»
// потребуют пакета intl, это модуль 03).
String formatDate(DateTime date) =>
    '${date.year}-${_two(date.month)}-${_two(date.day)}';

String _oneDecimal(double value) {
  final String text = value.toStringAsFixed(1);
  return text == '-0.0' ? '0.0' : text;
}

String _two(int value) => value.toString().padLeft(2, '0');
```

Разбор:

- `toStringAsFixed(1)` округляет до одной цифры после запятой **и всегда** показывает её (`10.0`, а не `10`).
- `text == '-0.0' ? '0.0' : text`: `-0.04` после округления даёт `'-0.0'`, пугающий «минус ноль»; убираем.
- `padLeft(2, '0')`: «8» → «08». `formatHour(DateTime(…, 8, 5))` даёт `08:05`.
- Приватные `_oneDecimal`, `_two`: подчёркивание перед именем **делает функцию приватной в файле**.

```dart
  expect(report.daily.last.description, 'Thunderstorm');
});
```

`forecastJson()` собирает ответ **на двое суток по часам** (48 значений): тест проверяет, что вторые сутки отброшены, и подмешивает целые числа туда, где в жизни тоже бывают целые.

Другие тесты файла: «строит правильный запрос» (имена переменных, единицы, пояс), «нет блока `current`», «`null` вместо температуры», «400 с причиной», «нет сети». Все дают `ServerFailure`/`ConnectionFailure`, а не краш.

**Экран на подделках** (`test/home_page_test.dart`, группа «ex02: вкладки»):

```dart
testWidgets('после поиска остаёмся на той же вкладке, данные новые', (tester) async {
  await pumpApp(tester);
  await tester.tap(barTab('Today'));

```

Приёмы:

- **`pageText`**: ищет текст **внутри `TabBarView`**, чтобы не путать с нижней панелью, где те же слова.
- **`tester.testTextInput.receiveAction(TextInputAction.search)`**: имитирует нажатие «поиск» на клавиатуре.
- **`scrollUntilVisible`**: прокручивает список, пока строка (23:00) не окажется на экране; без неё `find` не видит строки, которых ещё нет в дереве (ленивый `builder`).
- Тесты используют `FakeWeatherService` с `sampleReport`: 24 часа и 7 дней, чьи значения зависят от номера (`5.0 + h / 2`): строки отличаются, и тест различает их.

### 4.2 Симуляция: от JSON до экрана

Пусть ответ (упрощённо) такой, местное время Барселоны 28 ноября 14:15:

```text
current.time = "2026-11-28T14:15", temperature_2m = 12.3, weather_code = 2, wind_speed_10m = 10
hourly.time  = [ "2026-11-28T00:00", ... "2026-11-28T23:00", "2026-11-29T00:00", ... ]  (168)
```

| Шаг | Операция | Результат |
|---|---|---|
| 1 | `getJson`: 200, `utf8.decode(bodyBytes)`, `jsonDecode` | `Map` |
| 2 | `now = DateTime.parse("2026-11-28T14:15")` | 2026-11-28 14:15 |
| 3 | цикл по 168 часам; условие «тот же день» | пройдёт 24 значения (28-го) |
| 4 | `_number(10)`: `(10 as num).toDouble()` | `10.0` |
| 5 | `describeWeatherCode(2)` | `'Partly cloudy'` |
| 6 | `WeatherReport(...)` | отчёт |
| 7 | контроллер: `_emit(WeatherLoaded(report))` | уведомление |
| 8 | `ListenableBuilder` → `TabPage(tab: currently, state: Loaded)` | `CurrentView` |
| 9 | `formatTemperature(12.3)`, `formatWind(10.0)` | `12.3°C`, `Wind: 10.0 km/h` |

### 4.3 Симуляция: «сегодня» в разных поясах

Допустим, на телефоне в Барселоне 28 ноября 23:30, а пользователь ищет Токио. В Токио уже 29 ноября 07:30.

| Подход | Что покажет Today для Токио |
|---|---|
| по `DateTime.now()` телефона (28 ноября) | **вчерашние** часы Токио: неверно |
| по `current.time` из ответа (29 ноября 07:30) | сегодняшние часы Токио: верно |

Поэтому `now` берётся **из ответа**.

### 4.4 Симуляция: вкладка сохраняется

Пользователь на **Weekly**, в поле набрал «Rome» и нажал «поиск».

| № | Событие | Индекс вкладки | Что на странице |
|---|---|---|---|
| 1 | исходно | 2 (Weekly) | 7 дней Barcelona |
| 2 | `search('Rome')`: `Loading` | 2 | индикатор (на всех страницах) |
| 3 | геокодер: `[Rome IT]` | 2 | индикатор |
| 4 | погода: `Loaded(report Rome)` | 2 | 7 дней Rome |
| 5 | свайп вправо (Today) | 1 | часы Rome (тот же `state`) |

`DefaultTabController` выше `ListenableBuilder`, поэтому индекс не сбрасывается.

## 5. Альтернативы

| Подход | Суть | Плюсы | Минусы | Когда подойдёт |
|---|---|---|---|---|
| **Один запрос + `WeatherReport`** (выбрано) | см. выше | согласованные данные, один индикатор | ответ чуть больше | наш случай |
| Запрос на каждую вкладку при открытии | лениво | экономия трафика | три индикатора, рассинхрон, вкладки «пустые» при открытии | тяжёлые данные на вкладке |
| `Map<String, dynamic>` без моделей | быстро | ноль классов | опечатки в ключах видны только в рантайме | одноразовые скрипты |
| `json_serializable` / `freezed` | генерация моделей и `fromJson` | меньше ручного кода, `==`/`copyWith` | кодогенерация (`build_runner`), «колоночный» формат Open-Meteo всё равно требует ручной сборки | много моделей, стабильный формат |
| Dart-пакет `open_meteo` | готовый клиент | меньше кода | зависимость, чужие модели вместо наших | если не нужна учебная часть |
| `FutureBuilder` + `Future<WeatherReport>` | без контроллера | совсем коротко | повторные запросы, гонки и ошибки сложнее | один разовый запрос |
| Старые данные + полоска загрузки | `Loading(previous)` | нет «мигания» | сложнее состояние | коммерческое приложение |
| `current_weather=true` | старый способ «сейчас» | проще запрос | устаревший, меньше полей | не рекомендую |
| `timeformat=unixtime` | время числами | точность при смене часов | нужно самому переводить в локальное | когда важен перевод часов |
| `intl` для дат | локализованные «сб, 28 ноября» | красиво | пакет и локали | следующий модуль |
| `ListView` с готовым списком | без `builder` | проще | строит всё сразу | совсем короткие списки |
| `DataTable` для Weekly | таблица | колонки выровнены | тяжелее, плохо тянется на узком экране | широкие экраны |

## 7. Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| На экране «Unexpected answer» (ServerFailure) для любого города | Парсер не совпал с реальным ответом (имя поля, пояс, null) | `curl` из 1.6, сравнить с `_parse`; в `parseResponse` временно напечатать `error`/`stack` |
| `type 'int' is not a subtype of type 'double'` | `as double` на JSON-числе | Через `num`: `_number()` |
| Today показывает вчерашние часы | «сегодня» взят по часам телефона | Брать дату из `current.time` |
| Today пуст | Нет совпадающих дат (формат времени изменился) или `timezone` не `auto` | Проверить `current.time` и `hourly.time` в `curl` |
| `daily` пришёл без значений или 400 | Нет параметра `timezone` | Он обязателен для `daily` |
| Температура в °F или ветер в м/с | Единицы не указаны, API-умолчание изменилось | Явные `temperature_unit`, `wind_speed_unit` |
| `-0.0°C` на экране | Округление `-0.04` | `formatTemperature` уже чинит; если видите, не тот файл |
| Overflow на Currently в ландшафте | `Column` без прокрутки | `Center` + `SingleChildScrollView` + `Column(min)` |
| Overflow в Today/Weekly на низком экране | Заголовок отдельным виджетом над списком | Заголовок это элемент 0 списка |
| При поиске вкладка прыгает на первую | `DefaultTabController` оказался внутри `ListenableBuilder` | Поднять выше (как в `HomePage`) |
| Тест: `pumpAndSettle timed out` | На экране `CircularProgressIndicator` (бесконечная анимация) | Во время загрузки `pump(Duration)`, `pumpAndSettle` только на загруженных данных |
| Тест не находит «23:00  Slight rain» | Ленивый `builder` не построил строку | `scrollUntilVisible` |
| Тест находит текст дважды | Текст есть и на вкладке, и в нижней панели | `pageText(...)`: поиск внутри `TabBarView` |
| `RangeError (index)` в логе | Массивы разной длины в ответе | Это `ServerFailure` по замыслу; смотреть ответ |

## 8. Безопасность и риски

- **Недоверие к ответу.** Любая неожиданность в JSON становится `ServerFailure`, а не краш. Парсинг ничего не исполняет и не вставляет в запросы.
- **Данные не персональные, запрос персональный.** Мы отправляем Open-Meteo координаты (в том числе точку пользователя при GPS). Это передача местоположения третьей стороне: сказать об этом в политике конфиденциальности. Данные Open-Meteo лицензированы CC BY 4.0: в настоящем приложении нужно **указать источник**.
- **Некоммерческая лицензия.** Бесплатный API Open-Meteo только для некоммерческого использования (600 запросов в минуту, 5000 в час, 10 000 в сутки). Коммерческому приложению нужен платный план.
- **Не вводим в заблуждение.** Показываем «сегодня» по месту, единицы в подписях (`°C`, `km/h`): пользователь не должен гадать, что за число.
- **Лимиты и доступность.** Open-Meteo не обещает аптайм: поэтому ex03 (ошибки и повторы) это не декорация.
- **Риск «непроверенного кода»:** парсер сверен по документации, а не по живому ответу. Первый запуск и `curl` из 1.6 это обязательный шаг.

## 10. Что запомнить

**Dart:**

- JSON-массивы `hourly`/`daily` это **параллельные колонки**: объект «час» собирают по индексу.
- `switch`-**выражение** (`=>`, `_` для остального) для таблиц «код → текст»; `switch` по sealed/enum обязан быть полным.
- Образец объекта `WeatherLoaded(:final report)` проверяет тип и достаёт поле.
- Коллекция-цикл `[for (...) X]` строит список выражением.
- `DateTime.parse('...T14:15')` без пояса даёт «числа на часах», нам нужны именно они.
- `toStringAsFixed(1)`, `padLeft(2, '0')`, `'-0.0'` → `'0.0'`.

**Flutter:**

- `ListView.builder` строит строки лениво; заголовок это нулевой элемент списка (иначе overflow на низком экране).
- `DefaultTabController` **выше** того, что перестраивается: индекс вкладки не сбрасывается.
- `CircularProgressIndicator` ломает `pumpAndSettle`.
- `Center` + `SingleChildScrollView` + `Column(mainAxisSize: min)`: центр, пока хватает места, прокрутка, когда нет.

**Логика и реализация:**

- Один запрос на три вкладки: согласованность и один индикатор.
- «Сегодня» берут из **ответа** (время места), а не из часов телефона.
- Единицы просят у API **явно**.
- Всё «грязное» (`as`, `num`, парсинг дат) в одном месте; виджеты работают с чистыми моделями.
- Неожиданная форма ответа: `ServerFailure`, а не краш; чужой JSON не доверенный.
