## 1. Задача и с чего начать

### 1.1 Условия сабжа

- **Папка сдачи:** `mobileModule00`
- **Файлы для сдачи:** **`calculator_app`** и все необходимые файлы (именно так, а не `ex03`).
- **Запрещённые функции:** нет
- **Подсказка сабжа:** взять код из предыдущего упражнения и создать проект `calculator_app`. Можно использовать библиотеку `math_expressions` или аналогичную.

### 1.2 Проблема

Поля, созданные в ex02, должны показывать **выражение** и **результат выражения**. Нужно реализовать логику калькулятора поверх готового интерфейса.

### 1.3 Требования

**Функциональные:**

1. Операции: сложение, вычитание, умножение, деление.
2. Несколько операций в одном выражении с учётом приоритета (пример из сабжа: `1 + 2 * 3 - 5 / 2`).
3. Ввод **отрицательного числа** (нажатием `-` перед числом).
4. Ввод **десятичных** чисел.
5. Удаление последнего символа выражения (`C`).
6. Полная очистка выражения и результата (`AC`).

**Нефункциональные:**

1. **Приложение НИКОГДА не должно падать.** Сабж отдельно называет опасные случаи: некорректное выражение, деление на 0, очень большие числа.
2. Адаптивность из ex02 сохраняется.
3. `flutter analyze` без замечаний, `flutter test` зелёный.

### 1.4 Что не входит в задачу (non-goals)

- Скобки, степени, научные функции, история вычислений (их нет в списке кнопок).
- Оформление как на картинке сабжа.
- Точный формат длинных дробей: на картинке результат выводится полным `double` (`-33.333333333333336`), но сабж предупреждает, что демо может содержать необязательные дополнения.

### 1.5 Критерии успеха

- [ ] Проект называется `calculator_app`.
- [ ] Пример `59-89+20/6` даёт результат с учётом приоритета.
- [ ] Отрицательные и десятичные числа вводятся и считаются.
- [ ] `C` и `AC` работают, в том числе на пустом выражении.
- [ ] Ни один из случаев из матрицы проверок ниже не роняет приложение.
- [ ] `flutter analyze` и `flutter test` чистые.

### 1.6 Первый шаг (spike)

```bash
cd ~/Projects/Mobile/mobileModule00
```

Перенести код из ex02 и убедиться, что внешний вид и вывод в консоль работают. Затем отдельным маленьким экспериментом (например, в тесте) вычислить строку `1+2*3-5/2` выбранным способом (библиотека или собственный разбор) и посмотреть, что вернётся.

## 6. Запуск и проверка

### Матрица проверок «никогда не падает»

Каждую строку проверить на устройстве и желательно покрыть автотестом.

| Ввод | Что проверяем |
|---|---|
| `1/0`, `0/0`, `5/0*3` | Деление на ноль, бесконечность и NaN |
| `5+`, `5*`, `5-` и сразу `=` | Выражение, оборванное на операторе |
| `*5`, `/5`, `+5` | Выражение, начатое с оператора |
| `-5`, `--5`, `5--3`, `5*-3` | Отрицательные числа и несколько минусов подряд |
| `.`, `..`, `1..2`, `1.2.3` | Некорректные десятичные точки |
| `5.` и `=` | Число с точкой на конце |
| `=` на пустом выражении | Пустой ввод |
| `=` два раза подряд | Повторное вычисление |
| `C` и `AC` на пустом выражении | Удаление из пустого |
| `9999999999999999999*9999999999999` и дальше | Очень большие числа, переполнение, длина строки на экране |
| Очень длинное выражение (сотни символов) | Переполнение поля, прокрутка |
| `000123`, `0.0.0` | Ведущие нули |
| Быстрое многократное нажатие | Нет гонок и лишних перестроений |
| Поворот экрана посреди выражения | Состояние не теряется и не падает |
