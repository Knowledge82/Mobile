## 1. Задача и с чего начать

### 1.1 Условия сабжа

- **Папка сдачи:** `mobileModule00`.
- **Файлы для сдачи:** `ex00` и все необходимые файлы.
- **Запрещённые функции:** нет.

Текст задания: создать проект `ex00` средствами выбранного фреймворка. Для Flutter важно понять структуру проекта и, для этого упражнения, что такое виджеты и их состояния. Проект должен содержать **одну страницу** с виджетами:

- виджет **Text** и **кнопка под ним**, оба по центру **по горизонтали и по вертикали**;
- по нажатию кнопки в debug-консоль выводится **«Button pressed»**;
- приложение должно быть **адаптивным** (responsive).

Сабж (версия 2.3) отдельно предупреждает: «do not blindly trust the demos or pictures example which can contain not required additions». На картинке текст стоит на оливковом фоне, но этого требования в тексте задания нет.

### 1.2 Проблема

Нужно собрать минимальный экран и при этом показать, что вы понимаете три вещи: как устроен Flutter-проект, как из виджетов строится экран, и как сделать раскладку, которая не ломается на разных экранах.

### 1.3 Требования

**Функциональные:**

1. Одна страница.
2. Текст и под ним кнопка.
3. Оба элемента по центру экрана (по обеим осям).
4. Нажатие на кнопку печатает `Button pressed` в debug-консоль.

**Нефункциональные:**

1. **Адаптивность:** узкий и широкий экран, портрет и ландшафт, увеличенный системный шрифт. Никакого переполнения (жёлто-чёрных полос overflow).
2. `flutter analyze` без замечаний.
3. `flutter test` зелёный.
4. Код читаемый, и вы можете объяснить каждую его строку.

### 1.4 Что не входит в задачу (non-goals)

- Изменение интерфейса по нажатию (счётчик, смена текста). Задание этого не требует.
- Навигация между экранами, несколько страниц.
- Внешние пакеты кроме `material_ui`.
- iOS и десктопные платформы.
- Сложный дизайн и собственная тема, в том числе оливковый фон под текстом с картинки сабжа.

### 1.5 Критерии успеха

- [ ] Проект `ex00` создан и запускается (Chrome и/или телефон).
- [ ] Текст и кнопка по центру, кнопка под текстом.
- [ ] По нажатию в консоли `Button pressed`.
- [ ] Нет overflow в портрете, в ландшафте и при максимальном шрифте.
- [ ] `flutter analyze`: `No issues found!`
- [ ] `flutter test`: `All tests passed!`
- [ ] Можно объяснить: что такое виджет, чем Stateless отличается от Stateful и почему здесь достаточно Stateless.

## 2. Теория

### 2.1 Что такое Flutter и чем он отличается

Flutter это UI-фреймворк, язык у него Dart. Главное отличие от большинства кроссплатформенных инструментов: Flutter **не использует нативные кнопки**, а сам рисует каждый пиксель своим движком (Impeller). Поэтому интерфейс выглядит одинаково на всех платформах, а hot reload работает за секунды.

### 2.2 Всё есть виджет

Кнопка, текст, отступ, центрирование, тема, даже само приложение: всё виджеты. Экран описывается **деревом вложенных виджетов**.

### 2.3 Три дерева

```
Widget tree        →  Element tree         →  RenderObject tree
(описание,            (живой экземпляр,       (расчёт размеров
 неизменяемое,         хранит State,           и отрисовка)
 дёшево пересоздаётся) связывает остальные)
```

- **Widget** это неизменяемая конфигурация («хочу тут Text с таким текстом»). Пересоздаётся постоянно, и это нормально: виджеты очень лёгкие.
- **Element** решает, можно ли переиспользовать старый объект или надо строить заново.
- **RenderObject** делает реальную работу: считает размеры и рисует.

### 2.4 StatelessWidget и StatefulWidget

**StatelessWidget:** виджет без изменяемого состояния. Его вид зависит только от переданных параметров. Примеры: `Text`, `Icon`, `Padding`.

**StatefulWidget:** вид меняется со временем (счётчик, чекбокс, поле ввода). Он состоит из **двух классов**:

```dart
class Counter extends StatefulWidget {          // 1) неизменяемая «конфигурация»
  const Counter({super.key});
  @override
  State<Counter> createState() => _CounterState();
}

class _CounterState extends State<Counter> {    // 2) изменяемое «состояние»
  int _count = 0;

  @override
  Widget build(BuildContext context) {
    return ElevatedButton(
      onPressed: () => setState(() => _count++),
      child: Text('$_count'),
    );
  }
}
```

Зачем два класса: виджет неизменяем и пересоздаётся при каждом перестроении родителя, а `State` живёт долго (его держит Element). Поэтому `_count` не сбрасывается, хотя описание виджета уже новое.

**Что делает `setState`:** выполняет вашу функцию с изменением полей и помечает Element «грязным». На следующем кадре Flutter вызывает `build()` заново и сравнивает новое описание со старым. Перерисовывается только изменившаяся часть.

**Жизненный цикл State:**

```
createState → initState → didChangeDependencies → build ⇄ (setState) → dispose
```

`initState()` вызывается один раз (подписки, контроллеры), `build()` много раз, `dispose()` при удалении (освободить ресурсы, как `free()` в C).

### 2.5 Правило раскладки

> **Ограничения идут вниз, размеры вверх, позицию решает родитель.**

Родитель говорит ребёнку: «ты можешь быть шириной от A до B и высотой от C до D». Ребёнок выбирает размер в этих рамках и сообщает его родителю. Родитель решает, где его разместить. Из этого правила вытекает вся адаптивность Flutter: вместо жёстких пикселей вы строите раскладку из ограничений.

### 2.6 BuildContext и const

- **`BuildContext`** это положение виджета в дереве. Через него ищутся предки: тема (`Theme.of(context)`), размер экрана, навигатор.
- **`const`** создаёт объект на этапе компиляции в одном экземпляре. Для виджетов это оптимизация: Flutter видит, что константный виджет не изменился, и не перестраивает его поддерево.

## 3. Декомпозиция и решения

Задача раскладывается на четыре части: (1) создать проект, (2) собрать дерево виджетов, (3) подключить обработчик кнопки, (4) сделать раскладку адаптивной. Ниже ключевые развилки.

### Решение 1: StatelessWidget или StatefulWidget для страницы

- **Варианты:** Stateless; Stateful «на всякий случай».
- **Выбрано:** **Stateless**.
- **Почему:** нажатие кнопки ничего не меняет на экране, оно только пишет в консоль. Изменяемого состояния нет, значит Stateful добавил бы лишний класс без пользы. На вопрос «почему не Stateful?» правильный ответ: *«потому что у экрана нет изменяемого состояния»*.
- **Риски:** если позже потребуется менять экран по нажатию (счётчик), придётся переписать на Stateful. Это дёшево.

### Решение 2: `debugPrint` или `print`

- **Варианты:** `print`, `debugPrint`, `dart:developer log`.
- **Выбрано:** `debugPrint`.
- **Почему:** `print` вызывает предупреждение линтера `avoid_print` (а нам нужен чистый `flutter analyze`). `debugPrint` ограничивает скорость вывода, чтобы Android не терял длинные строки.
- **Нюанс:** в release-режиме `debugPrint` **не отключается автоматически** (это не `assert`). Не печатайте в него секреты.

| | `print` | `debugPrint` | `log` (dart:developer) |
|---|---|---|---|
| Виден в `flutter run` | да | да | да (в DevTools богаче) |
| Линтер `avoid_print` | предупреждает | чисто | чисто |
| Длинные строки на Android | могут обрезаться | троттлится | нормально |
| Импорт | не нужен | не нужен (через `widgets.dart`) | `dart:developer` |

### Решение 3: как сделать «адаптивно» и «по центру»

- **Варианты:**
  A. `Center` + `Column(mainAxisSize: min)`: минимум кода.
  B. То же + защитные слои: `SingleChildScrollView`, `ConstrainedBox(minHeight)`, `ConstrainedBox(maxWidth)`, `LayoutBuilder`, `SafeArea`.
- **Выбрано:** **B**.
- **Почему:** вариант A на портретном телефоне выглядит правильно, но **ломается** (overflow), когда контент не помещается: ландшафт на маленьком экране или крупный системный шрифт. Слово «responsive» в задании можно трактовать строго, поэтому берём надёжный вариант.
- **Что теряем:** код длиннее и вложеннее. Для понимания полезно разобрать каждый слой (см. раздел 4).

### Решение 4: импорт `material_ui`

- **Варианты:** `package:flutter/material.dart` (старый), `package:material_ui/material_ui.dart` (новый).
- **Выбрано:** новый.
- **Почему:** с Flutter 3.47 Material вынесен в отдельный пакет, у нас Flutter 3.50.0. Старый импорт ещё может работать, но считается устаревающим. Подробности: [README, раздел 4](../README.md#4-важно-material_ui-вместо-fluttermaterialdart).
- **Риск:** в интернете и в подсказках нейросетей повсюду старый импорт. Смешивать два импорта в одном файле нельзя.

### Решение 5: платформы проекта

- **Выбрано:** `flutter create --platforms=android,web`.
- **Почему:** меньше мусора и места (нет `ios/`, `linux/`, `macos/`, `windows/`). iOS на Linux всё равно не собрать, Linux-desktop без sudo не собрать.
- **Риск:** если позже понадобится другая платформа, её добавляют командой `flutter create --platforms=<платформа> .` в папке проекта.

## 4. Разбор кода

### 4.1 Полный `lib/main.dart`

```dart
import 'package:material_ui/material_ui.dart';

void main() {
  runApp(const MyApp());
}

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'ex00',
      debugShowCheckedModeBanner: false,
      theme: ThemeData(
        colorScheme: ColorScheme.fromSeed(seedColor: Colors.indigo),
      ),
      home: const HomePage(),
    );
  }
}

class HomePage extends StatelessWidget {
  const HomePage({super.key});

  void _onButtonPressed() {
    debugPrint('Button pressed');
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      body: SafeArea(
        child: LayoutBuilder(
          builder: (context, constraints) {
            return SingleChildScrollView(
              child: ConstrainedBox(
                constraints: BoxConstraints(minHeight: constraints.maxHeight),
                child: Center(
                  child: ConstrainedBox(
                    constraints: const BoxConstraints(maxWidth: 480),
                    child: Padding(
                      padding: const EdgeInsets.all(24),
                      child: Column(
                        mainAxisSize: MainAxisSize.min,
                        children: [
                          Text(
                            'A simple text',
                            textAlign: TextAlign.center,
                            style: Theme.of(context).textTheme.headlineMedium,
                          ),
                          const SizedBox(height: 24),
                          ElevatedButton(
                            onPressed: _onButtonPressed,
                            child: const Text('Click me'),
                          ),
                        ],
                      ),
                    ),
                  ),
                ),
              ),
            );
          },
        ),
      ),
    );
  }
}
```

Статус проверки: код написан под Flutter 3.50.0 и `material_ui`, но **перед сдачей его нужно прогнать** (`flutter analyze`, `flutter test`, запуск на Chrome и телефоне). См. раздел 6.

### 4.2 Разбор сверху вниз

#### Импорт

```dart
import 'package:material_ui/material_ui.dart';
```

- `import` подключает библиотеку. Это не `#include`: текст файла не копируется, подключается пространство имён.
- `package:` означает «из пакета, указанного в `pubspec.yaml`».
- `material_ui.dart` это главный файл пакета, который делает `export` сотен виджетов (`MaterialApp`, `Scaffold`, `ElevatedButton`, `ThemeData`, `Colors` и других).
- Ядро виджетов (`StatelessWidget`, `Column`, `Padding`, `Center`, `Text`, `SizedBox`) приходит через реэкспорт `widgets.dart`.

#### Точка входа

```dart
void main() {
  runApp(const MyApp());
}
```

- `main()` это тот самый `int main()` из C, только возвращает `void`.
- `runApp(...)` делает переданный виджет корнем дерева и запускает движок. Больше `main` ничего не делает.
- `const MyApp()` создаёт неизменяемый объект на этапе компиляции.

#### Класс `MyApp`

```dart
class MyApp extends StatelessWidget {
  const MyApp({super.key});
```

- `extends StatelessWidget`: наследуем виджет без состояния.
- `const MyApp({super.key})`: константный конструктор с именованным параметром `key`, который сразу передаётся родителю. Старая запись: `({Key? key}) : super(key: key)`. `key` помогает Flutter различать однотипные виджеты при перестановке в списках; здесь он не нужен, но писать его принято.

```dart
  @override
  Widget build(BuildContext context) {
```

- `@override`: «переопределяю метод родителя» (при опечатке в имени линтер подскажет).
- `build` описывает, как выглядит виджет. Он должен быть **чистым**: вернуть дерево и не делать побочных эффектов, потому что Flutter вызывает его когда захочет и часто.

```dart
    return MaterialApp(
      title: 'ex00',
      debugShowCheckedModeBanner: false,
      theme: ThemeData(
        colorScheme: ColorScheme.fromSeed(seedColor: Colors.indigo),
      ),
      home: const HomePage(),
    );
```

`MaterialApp` это корень Material-приложения: навигатор, тема, локализация. Без него `Scaffold` и `Theme.of(context)` не работают.

- `title`: название для переключателя задач.
- `debugShowCheckedModeBanner: false`: убирает красную ленточку DEBUG.
- `theme`: тема. `ColorScheme.fromSeed` генерирует согласованную палитру Material 3 из одного цвета. (Material 3 включён по умолчанию, отдельно `useMaterial3: true` писать не нужно.)
- `home`: первый экран.

#### Класс `HomePage`

```dart
class HomePage extends StatelessWidget {
  const HomePage({super.key});

  void _onButtonPressed() {
    debugPrint('Button pressed');
  }
```

`_onButtonPressed`: подчёркивание в начале означает **приватный** (виден только внутри файла). В Dart нет слов `private`/`public`, их заменяет `_`.

Дальше раскладка читается **снаружи внутрь**. Каждый виджет получает от родителя ограничения и выбирает размер в их рамках.

```dart
return Scaffold(
```

**`Scaffold`**: каркас экрана (фон, AppBar, body, FAB). Даёт телу место и цвет фона из темы.

```dart
body: SafeArea(
```

**`SafeArea`**: добавляет отступы там, где экран перекрыт вырезом камеры, статус-баром или панелью жестов.

```dart
child: LayoutBuilder(
  builder: (context, constraints) {
```

**`LayoutBuilder`**: спрашивает у родителя «сколько у меня места?» и передаёт ответ в `constraints`. Нам нужна `constraints.maxHeight`, то есть высота доступной области.

```dart
return SingleChildScrollView(
```

**`SingleChildScrollView`**: позволяет содержимому прокручиваться. Нюанс: внутри него высота **неограничена**, а `Center` при неограниченной высоте не растягивается и не центрирует по вертикали. Поэтому нужен следующий слой.

```dart
child: ConstrainedBox(
  constraints: BoxConstraints(minHeight: constraints.maxHeight),
```

**Первый `ConstrainedBox`**: «не ниже, чем вся видимая область». Так у `Center` появляется нижняя граница высоты, и есть что центрировать.

```dart
child: Center(
```

**`Center`**: помещает ребёнка в середину по обеим осям внутри доступного прямоугольника.

```dart
child: ConstrainedBox(
  constraints: const BoxConstraints(maxWidth: 480),
```

**Второй `ConstrainedBox`**: ограничивает ширину сверху (480). На телефоне (около 360) он ничего не меняет, на планшете или в широком окне браузера контент не растягивается.

```dart
child: Padding(
  padding: const EdgeInsets.all(24),
```

**`Padding`**: поля по 24 со всех сторон.

```dart
child: Column(
  mainAxisSize: MainAxisSize.min,
```

**`Column`**: вертикальный стек. `MainAxisSize.min` значит «занять по высоте ровно столько, сколько нужно детям». Без этого колонка растянулась бы на весь экран и центрировать было бы нечего.

```dart
children: [
  Text(...),
  const SizedBox(height: 24),
  ElevatedButton(...),
],
```

- **`Text`**: строка. Стиль берётся из темы (`Theme.of(context).textTheme.headlineMedium`), поэтому размер масштабируется вместе с системными настройками шрифта.
- **`SizedBox(height: 24)`**: пустое место между текстом и кнопкой.
- **`ElevatedButton`**: кнопка. `onPressed: _onButtonPressed` передаёт **ссылку на функцию** (без скобок), а не результат её вызова. Если написать `_onButtonPressed()`, функция выполнится при построении, а кнопка получит `void`: классическая ошибка. Если передать `onPressed: null`, кнопка станет серой и неактивной.

### 4.3 Симуляция: как ограничения идут вниз, а размеры вверх

Телефон 360×800, полезная область после `SafeArea` примерно 360×776 (цифры приблизительные, для понимания механизма):

```
Scaffold/SafeArea → LayoutBuilder:   maxHeight = 776
SingleChildScrollView:               высота 0..∞  (скролл снимает верхний предел)
ConstrainedBox #1:                   высота 776..∞  (minHeight = 776)
Center:                              просит ребёнка быть «сколько надо»,
                                     сам становится 360×776 (из-за minHeight)
ConstrainedBox #2:                   ширина 0..360 (лимит 480 не мешает)
Padding:                             внутри остаётся 312 по ширине
Column(min):                         Text ~36 + отступ 24 + Button ~40 = ~100 по высоте
                                     с Padding получается ~148
   ↑ размеры идут обратно вверх
Center:                              сдвигает блок на (776 − 148) / 2 ≈ 314 от верха
                                     и по горизонтали в центр
```

Три сценария из критериев:

- **Ландшафт** (область примерно 800×360): блок высотой ~148 помещается, центр сохраняется.
- **Огромный шрифт** (масштаб 200%): текст может перенестись на две строки, высота растёт. Если вылезет за доступную высоту, **включится скролл**, а не появятся полосы overflow.
- **Широкий экран:** `maxWidth: 480` не даёт блоку растянуться, он остаётся компактным в центре.

### 4.4 Симуляция: нажатие кнопки

```
1. Палец касается экрана → ОС передаёт событие касания движку Flutter.
2. Hit test: «какой RenderObject под этой точкой?» → RenderObject кнопки.
3. Арена жестов: касание распознаётся как tap (не drag, не long press).
4. InkWell внутри ElevatedButton запускает анимацию ряби (ripple).
   Это чисто визуальный эффект, его считает Flutter сам.
5. Вызывается ваш onPressed → _onButtonPressed().
6. debugPrint('Button pressed') → строка уходит в вывод → видна в консоли.
7. setState НЕ вызывался → Element не помечен «грязным» → build() НЕ запускается.
   Дерево виджетов прежнее (анимация ripple живёт отдельно).
```

Сравнение со Stateful: на шаге 6 был бы `setState(...)`, Element стал бы «грязным», на следующем кадре вызвался бы `build()`, новое дерево сравнилось бы со старым и перерисовалась бы только изменившаяся часть. Здесь ничего не меняется, поэтому Stateless правильнее.

### 4.5 Тест `test/widget_test.dart`

`flutter create` создаёт тест для приложения-счётчика. После замены `main.dart` он **упадёт**, поэтому заменяем его:

```dart
import 'package:flutter_test/flutter_test.dart';
import 'package:ex00/main.dart';

void main() {
  testWidgets('shows text and a button', (WidgetTester tester) async {
    await tester.pumpWidget(const MyApp());

    expect(find.text('A simple text'), findsOneWidget);
    expect(find.text('Click me'), findsOneWidget);
  });
}
```

- `testWidgets` собирает виджет в тестовой среде без устройства.
- `pumpWidget` строит дерево, `find.text` ищет виджет по тексту, `findsOneWidget` проверяет, что найден ровно один.
- Импорт `package:ex00/main.dart`: имя пакета берётся из `pubspec.yaml` (`name: ex00`).

## 5. Альтернативы

| Подход | Суть | Плюсы | Минусы |
|---|---|---|---|
| **`Center` + `Column(min)`** | Минимальный вариант | Коротко | Ломается при нехватке места (overflow) |
| **`LayoutBuilder` + скролл + `minHeight`** (наш) | Центр + страховка | Не ломается, понятная механика | Вложеннее, длиннее |
| **`MediaQuery.sizeOf(context)`** вместо `LayoutBuilder` | Размер всего экрана | Проще | Это размер экрана, а не реально доступного места (сплит-экран, складные телефоны) |
| **`IntrinsicHeight` + `Expanded`** | Растягивание через интринсики | Работает | Дороже по производительности, сложнее |
| **`Align(alignment: Alignment.center)`** | Вместо `Center` | Гибче (можно менять выравнивание) | Для центра эквивалентно |
| **`SizedBox.expand` + `Column` с `mainAxisAlignment.center`** | Центр через выравнивание колонки | Кратко | Не работает вместе со скроллом |
| **`CupertinoApp` + `CupertinoButton`** | Стиль iOS | Другой внешний вид | Лишний пакет `cupertino_ui`, цели задания не меняет |
| **`TextButton`/`FilledButton`/`OutlinedButton`** | Другие кнопки Material 3 | Любая подходит | Нет различий по требованиям |
| **Вынести `HomePage` в отдельный файл** | `lib/home_page.dart` | Хорошая привычка | Для ex00 избыточно |
| **`StatefulWidget` для страницы** | Лишнее состояние | Задел на будущее | Усложнение без пользы (см. решение 1) |

## 10. Что запомнить

**Про Dart:**
- `main()` это точка входа, `runApp()` запускает приложение.
- `const` создаёт неизменяемый объект на этапе компиляции; для виджетов это ещё и оптимизация.
- `super.key` это современная запись передачи `key` родителю.
- Подчёркивание в начале имени (`_name`) означает приватность (в пределах файла).
- `onPressed: функция` передаёт ссылку на функцию, `функция()` вызывает её сразу: классическая ошибка новичка.

**Про Flutter:**
- Всё есть виджет; экран это дерево виджетов.
- Три дерева: Widget (описание) → Element (экземпляр) → RenderObject (отрисовка).
- `StatelessWidget` не меняется сам; `StatefulWidget` хранит `State`, `setState` вызывает перестроение через `build()`.
- Для ex00 достаточно `StatelessWidget`: изменяемого состояния нет.
- Раскладка: ограничения идут вниз, размеры вверх, позицию решает родитель.
- Адаптивность строится на ограничениях (`LayoutBuilder`, `ConstrainedBox`), теме и скролле как страховке, а не на жёстких пикселях.
- `material_ui` (новый импорт) вместо `flutter/material.dart`.

**Про реализацию и процесс:**
- `debugPrint` вместо `print`: чистый `flutter analyze`.
- После `flutter create` обязательно поправить `widget_test.dart`, иначе тест красный.
- Центрирование внутри скролла требует `minHeight`, иначе бесконечная высота ломает `Center`.
- `flutter clean` после упражнения: `build/` и `.dart_tool/` быстро съедают home.
- Сначала spike (запустить пример), потом свой код: так проблемы окружения отделяются от проблем кода.
